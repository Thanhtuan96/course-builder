## Edge Coverage and Assumptions

- **Empty:** `assertCommandAllowed('')`, `assertCommandAllowed(null)` and `assertCommandAllowed('...')`
  still throw `command_denied` (the existing "No command supplied." branch) — asserted, not assumed.
- **Adjacency:** a name that becomes a denied name only after stripping (`npx.cmd`) and a name that is
  denied before stripping (`npx`) must both be denied; a name that resembles but is not denied
  (`node`, `python3`) must pass.
- **Encoding:** the check is case-insensitive and independent of separators; a trailing separator
  (`npx/`) normalizes to an empty name and is denied.
- **Ordering:** stripping runs **before** both the `bash` exception branch and the denylist check, so
  `bash.cmd` cannot slip through the `allowBash` branch.
- **Assumption A1:** `normalizeCommandName` is exported so the test can assert the normalization
  directly instead of only through the throwing wrapper. It is additive and not a behaviour change.
- **Assumption A2:** the allowlist is the `COMMANDS` map consumed by `buildPipeline`; there is no
  separate Set, so "closed" is proved by pinning `COMMANDS` exactly.

## Reversibility gates

- **Gate A (after Task 1):** the patch is a one-line normalization plus two exported constants. It is
  reversible (no data, no contract). Run the existing runner suites before touching the new test.
- **Gate B (before Task 2 finishes):** every existing runner test must still pass. If
  `test/studio-runner.test.js`, `test/security/**` or `studio/test/runner-*.test.js` goes red, the
  normalization changed behaviour beyond the denied set — revert and re-read the current
  `assertCommandAllowed` body rather than widening the edit.
