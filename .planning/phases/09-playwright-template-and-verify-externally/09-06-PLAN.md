## Edge Coverage and Assumptions

- **Empty:** no evidence → the submit action stays disabled with `submitRequiresEvidence`; no spec
  code → the review still runs but R1 clamps to `not_met` (facts have no spec files). A write-up-only
  submission is allowed and cannot pass. Stated, not implied.
- **Adjacency:** a review that fails to generate (no provider, model error) still stores the submission
  with the evidence and a computed `needs_work` verdict — the learner never loses their paste.
- **Ordering:** `revisionOf` points at the **last submission that existed before the new insert**, not
  the new row (research pitfall 10). Phase 5 writes the link row as `attempt_id` = previous attempt,
  `revised_id` = the new attempt, `feedback_id` = the explicit previous submission id, so the test reads
  the row back with `listRevisionLinks({ revisedId: attempt2.id })` and asserts that mapping (B3).
- **Encoding:** criterion labels come from `playwrightTemplate.rubric.r1…r7` in the UI language while
  the seeded `name`/`solid` stay in the course language (D-07); legacy `rating` values map through
  `normalizeStoredReview`.
- **Assumption A1:** `attempt` numbering and history order are the repo's (oldest first); the UI
  reverses for display only.
- **Assumption A2 (single revise surface):** the revise action is rendered **only** by the page — a
  primary `Button` in a callout above the form — and `ReviewPanel` receives `verdict` but no
  `onRevise`. The page owns `revisionTarget`; the panel never renders a second primary action and the
  prop is not left dead.
- **Assumption A3 (one spec-code source):** the page owns `spec = { path, code }` and derives
  `submittedFiles` from it once; the same object is passed to `ExternalEvidenceForm` and reaches
  `computeCapstoneFacts` (`input.files ?? submittedFiles`), so the evidence warnings and the R1 facts
  can never disagree.

## Reversibility gates

- **Gate A (after Task 1, tracer):** the slice paste → submit → stored evidence → computed verdict must
  be green before the review UI changes. The stored payload shape is a cross-phase contract; do not
  restructure it here.
- **Gate B (after Task 2):** the in-app path must still work — `capstone.test.js` and a manual read of
  the `capstoneHasTests` branch confirm the generated-capstone flow is untouched. Reverting the
  external branch is safe up to this point.
- **Gate C (after Task 3):** the revision link is one-way data (a `revision_links` row). Verify the
  link target before merging; a wrong target cannot be fixed without deleting rows.
