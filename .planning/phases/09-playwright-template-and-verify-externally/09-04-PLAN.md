## Edge Coverage and Assumptions

- **Empty:** zero evidence → the form shows the command block and no facts (no crash, no "0 passed").
  A zero-test paste shows the facts with a `no_tests` warning and a disabled confirm? No — confirm stays
  available (the learner may submit and be told it cannot pass); the warning is what blocks the pass
  in code (09-03). Stated, not implied.
- **Adjacency:** paste and upload are two entry points for one state — typing over an uploaded file
  replaces it, and clearing resets both. Covered by an acceptance criterion.
- **Encoding:** the paste is stored verbatim in `result.text` and only the parsed summary is shown; the
  file reader uses UTF-8 (`readAsText`).
- **Ordering:** spec files render in the parser's order (report order) and warnings render in the
  parser's order; no client-side sorting.
- **Assumption A1:** the primary command is the JSON-to-file recipe with `--project=chromium`; the UI
  never suggests `--reporter=list,json` on stdout, `--reporter=html`, trace zips or screenshots
  (Out of Scope + secret-leak risk).

## Reversibility gates

- **Gate A (after Task 1):** `EvidenceSummary` is presentational only; nothing persists. Free revert.
- **Gate B (before Task 3 finishes):** the escaping test must pass with a hostile paste. If any code
  path renders evidence through `Markdown` or `dangerouslySetInnerHTML`, stop — that is the phase's
  XSS gate, not a style choice.
- **Gate C:** `i18n-keys.test.js` and `i18n-catalogs.test.js` must be green in the same commit as the
  components that use the keys; a half-added namespace is a build break for the next two plans.
