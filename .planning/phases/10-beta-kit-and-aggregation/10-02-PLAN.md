## CLI contract (pinned)

Invocation: `node scripts/beta-aggregate.mjs <dir> [--json] [--roster <file>]`.

Arguments (`parseArgs(argv)`):

- `--help` / `-h` prints usage on stdout, exit `0`. No other flags are accepted; there is no `--flag=value` form.
- `--json` switches stdout to one JSON document.
- `--roster` consumes the next token (missing value is a usage error).
- The first non-flag token is `<dir>`; a second positional, an unknown `-…` flag or a missing `<dir>` is a usage error: usage text on stderr, exit `1`, stdout empty.

Scanning (`listReportFiles`):

- `readdirSync(dir)` then `.sort()` (default UTF-16 code-unit order — never `localeCompare`).
- Keep names ending `.json`, skip dotfiles, require `lstatSync(...).isFile()`; symlinks and directories are reported as invalid with reason `not a regular file` and are never read.
- Non-recursive. Exclude the roster by resolved path (`resolve(dir, name) !== resolve(roster)`).

Validation (`validateReportFile`):

- Size guard first: `size > 1048576` → reason `file too large: <size> bytes (max 1048576)`.
- `JSON.parse` failure → reason `invalid JSON: <message>`.
- `reportSchema.safeParse` failure → reason from issues[0]:
  `` `${issue.path.join('.') || '(root)'}: ${issue.code}: ${issue.message}` `` plus ` (+N more)` when there are further issues.
- Reasons are one line, at most ~160 characters, and never contain a newline.

Dedupe (`dedupe`):

- Iterate valid reports in filename order into a `Map` keyed by `participantId`.
- Replace when the candidate has a higher `generatedAtDayOffset`, or an equal offset and a lexicographically greater filename (string compare).
- Each replacement emits one warning: `duplicate participant <id>: dropped <droppedFile>, kept <keptFile>`.
- Invalid files never enter dedupe. Rows are emitted in kept-file-name order; roster-only rows follow, sorted by participant id.

Roster (`readRoster`):

- Read the file as UTF-8. If the first non-space character is `[`, `JSON.parse` must yield an array of non-empty strings.
- Otherwise split on `/[\s,]+/` and drop empties.
- Duplicated ids collapse; order is irrelevant because unknown rows are sorted.
- A missing/unparseable roster or a non-string array item is a fatal usage-style error: one stderr line, exit `1`, no report output.

Output — table (default):

- Header, then one row per participant, `padEnd` per column to the widest cell, single-space gap, no box drawing.
- Column order exactly: `participant day activated activeDays loops revisions w1 w2 w2Days capSub capEvidence verdict`.
- Cell rules: `activated`/`w1`/`w2` → `yes`/`no`; `loops` → sum of `byKind`; `revisions` → `quiz/tutor/ws/cap`; `verdict` → the verdict or `unknown`; every field a report cannot supply → the literal `unknown`.
- Invalid files print to stderr as `invalid <file>: <reason>`; duplicate warnings to stderr; a summary line `<n> valid, <m> invalid, <k> duplicate(s)` to stderr (allowed, must contain no `%`).
- stdout carries the table only.

Output — `--json`:

```json
{ "schemaVersion": 1, "ok": true,
  "participants": [{ "participantId": "...", "source": "professor-beta-report-...-d14.json",
    "generatedAtDayOffset": 14, "activated": true, "activeDayCount": 5, "loopTotal": 7,
    "loopsByKind": { "quiz_completed": 2, "recall_completed": 1, "answer_sent_for_review": 1,
                     "workspace_run": 2, "exercise_completed": 0, "capstone_checkpoint": 1 },
    "revisions": { "quiz": 1, "tutor": 0, "workspace": 1, "capstone": 0, "explicit": 1, "inferred": 1 },
    "week1Active": true, "week2Return": true, "week2MeaningfulDays": 3,
    "capstoneSubmissions": 1, "capstoneExternalEvidence": 0, "capstoneVerdict": null }],
  "invalid": [{ "file": "bad.json", "reason": "..." }],
  "duplicates": [{ "participantId": "...", "kept": "...d14.json", "dropped": "...d7.json" }],
  "unknown": ["..."] }
```

- One document on stdout, stable key order, no absolute paths, no timestamps.
- `ok` is the exit-code boolean. JSON keeps `null` for unavailable values; only the table renders `unknown`. `source: null` marks a roster-only row.

Exit codes and streams:

- `0` iff at least one report file was discovered and none was invalid (duplicates are warnings).
- `1` when any file is invalid, the directory is missing/not a directory/empty of `*.json`, the roster cannot be read, or the invocation is wrong.
- Directory-level errors: one stderr line, exit `1`, stdout empty in both modes. That line contains
  `not a directory` when `<dir>` is missing or is not a directory, and `no report files` when the
  directory holds no `*.json` entries. These two substrings are part of the contract, not a hint.
- `--json` still exits `1` when anything is invalid.
- No output, in any mode, may contain a `%` character, and no JSON key or table header may match
  `/\b(percent|percentage|rate|average|avg)\b/i`. Word boundaries are part of the contract:
  `generatedAtDayOffset` contains the letters `rate` inside `generated` and must pass.

Implementation shape (Claude's discretion, but keep these seams exported and pure):
`parseArgs`, `listReportFiles`, `validateReportFile`, `dedupe`, `readRoster`, `formatTable`,
`buildJsonDocument`, plus `main(argv)` returning the exit code and `process.exitCode = main(...)`
behind a realpath `isMain()` check, matching `scripts/sync-shared.mjs`.
