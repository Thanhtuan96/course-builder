<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Studio/CLI action -> repo write function | Untrusted learner content is present in the payload; only the repo decides what becomes an event. |
| repo -> learning_events row | The event must contain enum/number/day metadata only, never content. |
| learning_events -> exportAll/backup | A leaked field here leaves the machine with the learner's backup. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | Tampering | `repo/index.js` emission hooks | high | mitigate | Emit after a successful write, only on the create path; one event per action tests; inner-checks discriminator for `saveRunResult`; idempotent capstone early-return covers repeats. |
| T-05-06 | Tampering | memory/IndexedDB/SQLite/CLI parity | medium | mitigate | All emission lives in the shared repo, never in pages; adapter contract in 05-05 runs the same assertions against memory, IndexedDB, remote/SQLite and the CLI store. |
| T-05-07 | Information Disclosure | `events.js` meta and `learning_events` | high | mitigate | Per-kind key whitelist, enum-only strings, reject arrays/free strings, 512-character serialized cap before write, mandatory sentinel test over rows and the learning_events backup slice. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package install in this plan; dependencies are frozen by Phase 1. A proposed install stops the task for the package-legitimacy gate. |
</threat_model>
