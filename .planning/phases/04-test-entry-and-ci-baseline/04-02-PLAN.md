<threat_model>
**ASVS level:** L1; block on high.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub event → workflow expression | PR titles, branch names, commit messages, and event payloads are untrusted input to workflow steps. |
| Workflow → repository token | The automatically issued GitHub token crosses into checkout and every step. |
| Workflow → npm cache | Cached packages and tool binaries cross branch and run boundaries. |
| Workflow → registry | `npm ci` and the smoke's temp-project install fetch code from the registry. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-03 | Elevation of Privilege / Tampering | `.github/workflows/ci.yml` `run` steps | high | mitigate | Use only static matrix values in `run`; never interpolate event payloads, PR titles, branch names, or commit messages. Use `pull_request`, not the target variant. |
| T-04-04 | Elevation of Privilege / Information Disclosure | GitHub token and secrets | high | mitigate | Top-level `permissions: contents: read`; no repository secrets, publish token, or write scope; `actions/checkout@v4` and `actions/setup-node@v4` only. |
| T-04-05 | Tampering | npm cache | medium | mitigate | `setup-node` cache is keyed by the four lockfiles; no custom cache writes or restore of executables; CI installs only with `npm ci`. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No packages are added (D-14). CI installs only the locked tree from committed lockfiles; the smoke's temp-project install is the existing stranger-install assertion. |

Every threat has a disposition. No high-severity threat is accepted.
</threat_model>
