<objective>
Split the `en.json` / `vi.json` monoliths into per-namespace files, make catalog loading
glob-driven, and remove the render-time module-state mutation from `useT`.
</objective>

| T-06-05 | A per-language namespace file is missing or has divergent keys, so `translate` silently falls back to English and the learner sees mixed-language UI | Medium | Pair test reads both directories, asserts identical file sets and per-namespace deep key parity; global `catalogKeys` parity test remains | None |

## Reversibility gates

- **Gate A (after Task 1, tracer):** do not touch the other 19 namespaces until the errors-namespace
  slice passes focused tests. If the glob probe fails under Vitest, stop and escalate; the tracer is
  revertible with no user-visible change.
- **Gate B (before Task 2 deletes the monoliths):** run the file-set count (`20` files per language)
  and key-parity tests against the new files first. Deleting `en.json`/`vi.json` is the one-way step
  in D-06; rollback after this point is a git revert only (no runtime data migration).
