<objective>
Turn a wrong-language JSON result into a typed, retryable provider error at the single
`createGenerateJson` choke point so syllabus, quiz, flashcard and capstone generation all stop
silently returning the wrong language.
</objective>

| ID | Threat | Severity | Mitigation in this plan | Residual |
|----|--------|----------|-------------------------|----------|
| T-06-01 | The model answers in the wrong language twice and the app silently stores/shows that content as if it were valid, so the learner cannot tell the lesson is in the wrong language. Rated High because generated content is persisted (syllabus, quiz, flashcards, capstone) and later rendered as the authoritative course material — a wrong-language fallback is a durable correctness defect, not a transient UI glitch | High | Re-check the repaired value; throw `wrong_language` on mismatch or repair-validation failure; never return the first value | None for generated JSON; NewCourse creation still swallows capstone errors intentionally, but no wrong-language capstone is stored |
| T-06-06 | The UI shows an English-only error because the error carries a custom message/hint that defeats `ErrorNotice` localization | Low | Construct the error with no custom message/hint; copy lives in `ERROR_HINTS` and the errors namespace both languages | None |

**Severity rationale:** T-06-01 is High (not Medium): the wrong-language JSON is written into the
course record and displayed afterwards as trusted syllabus/capstone content, so the defect persists
across sessions and the learner has no signal that the material is invalid. A transient failure would
be Medium; a persisted authoritative-content defect is High.
</threat_model>

## Reversibility gates

- This plan adds a new error outcome but no data migration. Rollback is a git revert of this plan's
  commit; generated content from before the change is unaffected.
- **Gate A:** do not add the catalog keys until `WrongLanguageError` is default-constructible and the
  `errors.js` probe passes. The catalog keys are additive and independently revertible.
- **Gate B:** do not change the `bad_json` ladder; if a test fails because `bad_json` is expected,
  stop and fix the language branch rather than weakening the existing ladder.

  <action>
  Append `wrong_language` to `ERROR_CODES`. Add an English default to `ERROR_HINTS` using the
  agreed copy: “The model answered in the wrong language twice. Try again, or pick a stronger
  model.” Export `class WrongLanguageError extends ProviderError` whose default constructor takes an
  optional `{ cause }` object, calls `super('wrong_language')` with no custom message or hint, sets
  `this.name = 'WrongLanguageError'`, and preserves the cause. Export a factory

  `ProviderError`, `providerError` or `isAbortError` behavior for existing codes.
  </action>

  - A supplied cause is preserved on `error.cause`; no custom message/hint is passed.
  </acceptance_criteria>
  <verify>
    <automated>node -e "import('./studio/src/lib/ai/errors.js').then(m=>{const e=new m.WrongLanguageError({cause:new Error('x')});if(e.code!=='wrong_language'||e.name!=='WrongLanguageError'||!(e instanceof m.ProviderError))throw new Error('bad error shape');if(e.message!==m.ERROR_HINTS.wrong_language||e.hint!==m.ERROR_HINTS.wrong_language)throw new Error('default copy lost');if(!e.cause)throw new Error('cause lost');if(m.wrongLanguageError().code!=='wrong_language')throw new Error('factory');console.log('ok')})"</automated>
    <fails_when>Non-zero exit or any thrown message: bad error shape, default copy lost, cause lost, or factory.</fails_when>
