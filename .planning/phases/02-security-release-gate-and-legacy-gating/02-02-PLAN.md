  <action>
  Replace the body of `installGuards(router, { getToken, origins, allowNonLoopback, extraHosts,
  jsonLimit })` with the single order: Host guard → Origin/preflight → token → JSON content-type
  gate → `express.json({ limit, strict: true })` → body-parser error mapper (D-11).
  - Host: read the raw `Host` header via `security.isAllowedHost`; reject 403 `forbidden_host`. The
    client-address loopback check stays (`isLoopbackAddress(req.socket.remoteAddress)`), and
    `allowNonLoopback` relaxes it only for the explicitly configured host (D-12).
  - Origin: in the default exact-allowlist mode, an unknown origin and the literal `null` → 403
    `forbidden_origin`; absent Origin continues to the token guard (D-13). In
    `STUDIO_ORIGINS=*` mode a non-null request origin is echoed and **allowed** (unknown is not a
    403 in this mode), `null` is still 403, `Vary: Origin` is set, and `*` is never emitted (D-22).
    Preflight follows the same mode split: default mode rejects an unknown origin with 403; wildcard
    mode allows and echoes a non-null origin and rejects `null`. A successful preflight is Host +
    Origin only, then 204 with exact `Access-Control-Allow-Origin`, methods `GET, POST, OPTIONS`,
    headers `Content-Type, X-Studio-Token`, `Access-Control-Allow-Private-Network: true` when
    requested.
  - Token: `getToken()` (function, not a frozen string) compared with `timingSafeEqual`; OPTIONS is
    exempt; missing/invalid → 401 `unauthorized`, including when no Origin header exists (D-04/D-13).
  - JSON: `requiresJsonContentType` → 415 `unsupported_media_type` before the parser; parser errors
    map `entity.parse.failed` → 400 `invalid_json`, `entity.too.large` → 413 `payload_too_large`,
    charset/encoding → 415. Never return Express's HTML error page (research §2.3).
  - Re-export `DEFAULT_ORIGINS` and `parseOrigins` from `web/security.js` so existing importers stay
    valid (D-14). Export `installGuards` and a small `buildOriginSet({ envValue, ownPort, legacyDev,
    studioPort })` that adds the server's own origin(s) and `5173` only in legacy dev (D-28).
  Update `test/security/guards.test.js` with the full matrix from research §2.7: no token 401, valid
  token 200, evil origin 403, null origin 403, spoofed Host 403, localhost/[::1] any port 200,
  text/plain 415, malformed JSON 400, oversized 413, preflight 204 without a token, and a header
  assertion that ACAO is never literally `*`. Add one explicit wildcard-mode case: with
  `STUDIO_ORIGINS=*`, a non-null unknown origin is allowed and echoed (not 403), `Origin: null` is
  still 403, and a default-mode unknown origin is 403. Use `test/security/helpers/app.js` (Task 5)
  or a local router harness with the Plan 01 token getter.
  </action>
