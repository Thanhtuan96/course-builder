## Key User Decisions (LOCKED - implement exactly)

1. **Trigger Timing (Hybrid)**:
   - Brief bridge after `professor:done` marks a section complete (reinforcement)
   - Fuller bridge when learner runs `professor:next` to advance to new section (preparation)

2. **Bridge Format (Learner chooses)**:
   - Text summary: "In Section 3 you learned X. In Section 4 you'll build on this by learning Y."
   - Concept map: Visual-style arrows showing "X → connects to → Y → enables → Z"
   - Socratic prompts: Questions that help learner discover connections themselves

3. **Concept Map Storage**: LEARNING-LOG.md with "Concept Thread" section

4. **Insight Threading**: Forward references like "Previously: Spotter helped you realize X → Now: This connects to Y"

Create agents/navigator.md with:

1. **Frontmatter** (following coach.md pattern):
   - name: navigator
   - description: Section bridges and concept threading agent
   - tools: Read, Write
   - color: cyan

2. **Core Principle**: Navigator is additive, never blocking. Present bridge, then let learner continue.

3. **Activation Triggers** (two modes per user decision):
   - After professor:done (brief bridge): Read LEARNING-LOG.md for current section concepts, generate 2-3 sentence bridge, ask format preference, append to Concept Thread
   - After professor:next (fuller bridge): Read LEARNING-LOG.md for previous section + LECTURE.md for next section topics, generate comprehensive bridge, check Coach's watch-this flags, append to Concept Thread

4. **Bridge Formats** (three options per user decision):
   - Text Summary: "In Section {N} you learned {concept}. In Section {N+1} you'll build on this by learning {next-concept}. The connection is {how they relate}."
   - Concept Map: Use simple arrows "X → Y → Z" with "enables" relationships. Max 3-4 items per line.
   - Socratic Prompts: Questions that help learner discover connections themselves

5. **Format Preference**:
   - Store in LEARNING-LOG.md as "preferred_format: text|concept-map|socratic"
   - Use stored preference as default

6. **Concept Threading**:
   - Read LEARNING-LOG.md for previous sections' concepts
   - Thread Coach's "watch-this" flags forward: "Previously: [watch-this] → Now: This connects to [new concept]"
   - Append Concept Thread entries to LEARNING-LOG.md

7. **Data Access**:
   - Read: COURSE.md (section numbers, titles), LECTURE.md (key topics), LEARNING-LOG.md (Reasoning Trail, Attempt Log, Concept Thread)
   - Write: LEARNING-LOG.md (Concept Thread section)

8. **Delegation**:
   - After presenting bridge: "That's the bridge from Section {N} to Section {N+1}. Run `professor:next` when ready to start the lecture — or `professor:navigator` anytime to see your concept thread."

9. **Concept Thread LEARNING-LOG.md Format**:
   ```markdown
   ## 🧭 Concept Thread

   ### Section 2 → Section 3
   **Format used:** text-summary
   **Previous:** Closures — functions that "remember" their scope
   **Next:** Higher-order functions — functions that take/return functions
   **Connection:** "Closures enable higher-order functions because you can return a function that still has access to its original scope."

   ### Section 3 → Section 4
   **Format used:** concept-map
   **Thread:** Higher-order → enables → callbacks → enables → event handlers

   ⚠️ Forward reference from Section 1:
     Previously: "You identified that edge cases matter" → Now: "This connects to defensive programming in error handling"
   ```
