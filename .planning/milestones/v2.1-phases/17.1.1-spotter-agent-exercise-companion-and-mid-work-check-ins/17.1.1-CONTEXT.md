**What this phase delivers:**

- New command `professor:spotter` for explicit check-in requests
- Hint system enhancement (reads attempt log before applying layers)
- Lecture delivery includes Spotter reminder

</domain>

<decisions>
## Implementation Decisions

All decisions below are locked from the approved spec:

### Core Principle
- Spotter NEVER gives hints, code suggestions, or reassurance — only asks questions that move learner toward understanding their position

### Activation
- **Active only** — `professor:spotter` command (learner invokes explicitly)
- No passive detection (not implementable in Markdown plugin)

### Response Routing
| Response | Spotter Action |
|----------|---------------|
| (a) rough idea, not started | "What's the first smallest thing you could try?" |
| (b) started, hit a wall | "What exactly is the wall? Describe it." |
| (c) something working, unsure | "What makes you unsure? Walk me through your logic." |
| (d) done, ready for review | Routes to Coach for `professor:review` |

### Data Ownership
- Spotter reads COURSE.md (active exercise)
- Spotter writes to LEARNING-LOG.md (Attempt Log section only)
- Coach reads Attempt Log before review

### Commands
- `professor:spotter` — new command, owned by Spotter
- `professor:hint` — enhanced to read attempt log first
- `professor:next` — add Spotter reminder at end

### Dependencies
- Requires Phase 17.1 (Coach Agent) complete first
- LEARNING-LOG.md created by Coach, Spotter appends to it
- Spotter handoff to Coach for review flow

</decisions>
