<task type="auto">
  <name>Task 1: Modify professor:next to auto-create exercise files + write Active exercise to COURSE.md</name>
  <files>commands/professor/next.md</files>
  <action>
Modify professor:next command to:
1. Create exercise file after writing LECTURE.md
2. Write "Active exercise" field to COURSE.md

Steps after LECTURE.md is written:

1. Determine course location:
   - Check for learning/{slug}/ first (worktree courses - Phase 7)
   - Fall back to courses/{slug}/ (legacy)

2. Determine exercise file path:
   - Use exercises/01-intro.js pattern (simple, sequential naming)
   - Extract section number from COURSE.md for prefix
   - Determine file extension based on topic type (js, ts, py, sql, etc.)

3. Detect topic type (standalone vs framework):
   - Parse COURSE.md for hints about topic type
   - Common framework indicators: React, Next.js, Express, Django, Vue, etc.
   - Default to standalone if unclear

4. Create exercise file template:
   - Skip if file already exists (backwards compatible)
   - Write template file with:
     - Comments describing the exercise task
     - Function signatures / skeleton code
     - TODO comments marking where to implement
   - DO NOT write working code - only skeleton

5. Update COURSE.md:
   - Add/update "Active exercise" field:
     ```
     **Active exercise**: exercises/01-intro.js
     ```
   - This field is read by review/hint/stuck commands

Example template:
```javascript
// Exercise: [Task description]
// See LECTURE.md for full instructions

// TODO: Implement [specific task]
function yourFunction(param) {
  // Your code here
}

// TODO: Add test cases
module.exports = { yourFunction };
```
  </action>
  <verify>
<automated>cat commands/professor/next.md | grep -q "exercises/section-"</automated>
  </verify>
  <done>professor:next creates exercise template file and writes "Active exercise" to COURSE.md</done>
</task>
