Create agents/spotter.md following the spec:

- Core Principle: Spotter NEVER gives hints, code suggestions, or reassurance — only asks questions that move learner toward understanding their position
- Activation: Active only via `professor:spotter` command (explicit learner invocation)
- Response Routing table:
  - (a) rough idea, not started → "What's the first smallest thing you could try?"
  - (b) started, hit a wall → "What exactly is the wall? Describe it."
  - (c) something working, unsure → "What makes you unsure? Walk me through your logic."
  - (d) done, ready for review → Routes to Coach for professor:review
- Data: Reads COURSE.md (active exercise), writes to LEARNING-LOG.md (Attempt Log section)
- What Spotter does NOT do: No hints, no code suggestions, no reassurance, no evaluation

Use frontmatter format matching existing agents (name, description, instructions).

Create commands/professor/spotter.md:

- Command triggers Spotter agent
- Presents position check-in prompt:
  ```
  Quick check-in — where are you right now?

  a) I have a rough idea but haven't started writing yet
  b) I've started but hit a wall
  c) I have something working but not sure it's right
  d) I think I'm done — ready for review
  ```
- After learner responds (a/b/c), Spotter asks follow-up question per routing table
- After learner responds (d), Spotter says "Let me hand you to Coach for review" and invokes Coach agent
- Appends entry to Attempt Log in LEARNING-LOG.md: timestamp, learner response, sticking point (if any)

Format: standard command file with frontmatter (name, description) + Behavior section.
