<task type="auto">
  <name>Task 1: Enhance exercise generation in commands/professor/next.md</name>
  <files>commands/professor/next.md</files>
  <action>
Enhance the "After writing LECTURE.md, auto-create the exercise file:" section in commands/professor/next.md:

1. **Improve topic type detection** - Add logic to detect whether a section is:
   - Coding exercise (programming language, algorithms, data structures, etc.)
   - Non-coding exercise (marking, math proofs, conceptual, analysis, etc.)
   
   Detection heuristics:
   - Coding keywords: "implement", "function", "write code", "program", "algorithm", "build", "create component", "API", "database", "query", "class", "method"
   - Non-coding keywords: "analyze", "explain", "compare", "prove", "mark", "calculate", "design", "describe"
   - Technology detection from course name: React → .jsx, Python → .py, SQL → .sql, etc.

2. **For coding exercises** - Generate better skeleton code:
   - Include clear exercise description in comments at top
   - Add function signature with appropriate parameters
   - Include TODO comments for each required implementation
   - Add example input/output in comments
   - Make it self-contained: include all context needed in the file itself
   
   Template:
   ```javascript
   // ========================================
   // Exercise: [Exercise Title]
   // ========================================
   // 
   // Objective: [1-2 sentences what user should accomplish]
   // 
   // Example:
   //   Input: [example input]
   //   Output: [expected output]
   //
   // Constraints:
   //   - [Constraint 1]
   //   - [Constraint 2]
   //
   // See LECTURE.md for concept explanation.
   // Work on this file directly - you can complete it without the lecture visible.
   // ========================================

   // TODO: [Task 1 description]
   function yourFunction(param) {
     // Your implementation here
   }

   // TODO: [Task 2 description - if applicable]
   // function anotherFunction() { }

   module.exports = { yourFunction };
   ```

3. **For non-coding exercises** - Generate pure instructions:
   - No code scaffolding
   - Clear numbered instructions
   - Space for user to write their answer
   - Reference to what constitutes a correct answer
   
   Template:
   ```markdown
   # Exercise: [Exercise Title]

   ## Objective
   [What user should accomplish - 1-2 sentences]

   ## Instructions
   Complete the following:
   
   1. [Instruction 1]
   2. [Instruction 2]
   3. [Instruction 3]

   ## Your Answer
   [Space for user's response - either free text or specific format]

   ## Verification
   [What makes a good answer - criteria for self-verification]

   ## Resources
   - [Reference to LECTURE.md section]
   - [Any additional hints without giving the answer]
   ```

4. **Technology auto-detection** - Determine file extension:
   - React/JS/Node → .jsx or .js
   - TypeScript → .ts
   - Python → .py
   - SQL → .sql
   - Go → .go
   - Rust → .rs
   - Non-coding → .md

5. **Make exercises self-contained** - Include in the exercise file:
   - Exercise title and objective
   - All necessary context/instructions
   - Example cases
   - Constraints
   - Verification criteria (not the answer)
