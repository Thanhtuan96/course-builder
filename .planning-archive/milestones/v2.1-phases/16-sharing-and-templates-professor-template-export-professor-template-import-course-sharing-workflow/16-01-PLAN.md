<task type="auto">
  <name>Task 1: Create professor:template-export command</name>
  <files>commands/professor/template-export.md</files>
  <action>
Create command file for exporting course to template:

1. **When user runs `professor:template-export`:**
   - Check if in a course directory (learning/{slug}/ or courses/{slug}/)
   - If not in course: error "Run this command from within a course directory"
   
2. **Read COURSE.md** and extract:
   - Course name (from frontmatter or title)
   - All sections with status ⬜ (not started), 🔄 (in progress), ✅ (completed) — include all
   - Section titles, descriptions, learning objectives
   - Difficulty level, technology type from frontmatter
   
3. **Read CAPSTONE.md** and extract:
   - Project brief
   - Suggested features
   - Technical approach hints
   
4. **Write TEMPLATE.md** to course directory with:
   - JSON frontmatter: name, version (1.0), difficulty, type, author, description, tags, estimated_hours, created_date, template_author (original creator)
   - Sections as Markdown: ## N. Section Title with bullet objectives
   - All sections marked ⬜ (Not Started) regardless of original status
   - Capstone section with brief + features + hints
   
5. **Confirm to user:**
   - "Template exported to {path}/TEMPLATE.md"
   - "Share this file to let others import your course structure"
  </action>

<task type="auto">
  <name>Task 2: Create professor:template-import command</name>
  <files>commands/professor/template-import.md</files>
  <action>
Create command file for importing template to create course:

1. **When user runs `professor:template-import` or `professor:template-import <path>`:**
   - If path not provided: check current directory for TEMPLATE.md
   - If not found in current dir: prompt user for template path
   - Validate path exists and is readable
   
2. **Read and validate TEMPLATE.md:**
   - Parse JSON frontmatter — reject if missing or invalid with clear error
   - Required frontmatter: name, version
   - Validate version: if older than current (1.0), attempt migration
   - Extract sections: must have ## N. Section Title format
   - Extract capstone: must have project brief
   
3. **Preview template to user:**
   - Show: course name, difficulty, author, section count, estimated hours
   - List all sections with objectives
   - Show capstone brief
   - Ask: "Create course from this template? (yes/no)"
   
4. **On user confirmation:**
   - Generate slug from template name (same as new-topic)
   - Create git worktree at learning/{slug}/ (same as new-topic)
   - Write COURSE.md with:
     - Frontmatter: name, difficulty, type, author (from template), template_source (original author)
     - Sections: all from template, all marked ⬜ Not Started
   - Write CAPSTONE.md with template capstone content
   - Write NOTES.md (empty)
   
5. **Confirm to user:**
   - "Course '{name}' created at learning/{slug}/"
   - "Run professor:next to start your first section"
  </action>
  <verify>
<automated>File exists at commands/professor/template-import.md with content matching "professor:template-import"</automated>
  </verify>
  <done>Template import command created that reads TEMPLATE.md, validates schema, shows preview, creates new course with pre-built syllabus (reuses new-topic workflow for course creation)</done>
</task>
