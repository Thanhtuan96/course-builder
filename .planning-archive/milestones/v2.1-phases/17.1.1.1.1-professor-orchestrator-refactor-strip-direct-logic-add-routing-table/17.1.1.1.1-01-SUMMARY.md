## Implementation Details

### Routing Table Structure

The YAML routing table supports three routing types:

1. **Simple Delegation** (`delegate_to`): Single agent delegation
   - `professor:review` → coach
   - `professor:stuck` → coach
   - `professor:spotter` → spotter
   - `professor:progress` → navigator
   - `professor:navigator` → navigator

2. **Multi-Step Flow** (`flow` array): Sequence of agents/actions
   - `professor:done`: coach → professor_mark_complete → navigator
   - `professor:next`: navigator → researcher → professor_write_lecture → navigator

3. **Internal Actions** (`action`): Professor handles directly
   - `professor:syllabus` → read_course_file
   - `professor:new-topic` → create_course
   - `professor:capstone` → read_course_file
   - `professor:discuss` → handle_discuss
   - `professor:capstone-review` → capstone_review
   - `professor:export` → export_course
   - `professor:note` → handle_notes
   - `professor:archive` → archive_course
   - `professor:recall` → spaced_repetition_recall
   - `professor:schedule` → manage_schedule
   - `professor:hint` → provide_hint_layers

### Actions Section

All internal actions are documented in the `actions:` section:
- `professor_mark_complete`: Calculate duration, update COURSE.md, create flashcards
- `professor_write_lecture`: Write LECTURE.md with section content
- `read_course_file`: Read COURSE.md or CAPSTONE.md
- `create_course`: Create new course from user input
- `handle_discuss`: Conceptual Q&A
- `capstone_review`: Full project review
- `export_course`: Export to Notion/Obsidian
- `handle_notes`: Manage NOTES.md
- `archive_course`: Archive to .course_archive/
- `spaced_repetition_recall`: Recall session
- `manage_schedule`: Schedule management
- `provide_hint_layers`: Hint layer delivery
