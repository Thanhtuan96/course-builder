**Required sections (in logical reading order):**

1. **Header / Title** — Project name, one-sentence hook, badges if desired (optional)

2. **What is this?** — 1-2 paragraphs explaining the Socratic learning method. Key points to convey:
   - The professor asks questions rather than giving answers
   - The professor will NOT write code for the user — this is intentional by design, not a limitation
   - The learner builds real understanding by solving problems themselves
   - This is different from asking Claude to just give you code ("the shortcut route")
   - Suitable for all levels: Beginner → Intermediate → Advanced → Expert

3. **Requirements** — Claude Code (specify version range if known), Node.js (for hooks), and that Notion/Obsidian MCP setup is only required if the user wants to use the export feature

4. **Install** — Numbered steps, no Googling required:
   - Step 1: Clone the repo (provide the git clone command)
   - Step 2: Create the plugins directory if it doesn't exist: `mkdir -p ~/.claude/plugins`
   - Step 3: Symlink or move the repo: `ln -s "$(pwd)/course-learning-plugin" ~/.claude/plugins/professor` (or instruct user to clone directly into that path)
   - Step 4: Restart Claude Code / reload plugins

5. **Notion MCP Setup** (required for `professor:export` to Notion):
   - When to do this: only needed if the user wants to export to Notion
   - Step-by-step: Create a Notion integration at notion.so/my-integrations, copy the API token
   - Create or edit `.mcp.json` in the user's project root (or `~/.claude/settings.json` depending on Claude Code version)
   - Provide a complete, copy-pasteable JSON snippet:
     ```json
     {
       "mcpServers": {
         "notion": {
           "command": "npx",
           "args": ["-y", "@modelcontextprotocol/server-notion"],
           "env": {
             "NOTION_API_TOKEN": "your-notion-integration-token-here"
           }
         }
       }
     }
     ```
   - Note: Replace `your-notion-integration-token-here` with the token from the Notion integrations page
   - Note: The destination Notion page must have the integration shared with it (Settings → Connections)

6. **Obsidian MCP Setup** (required for `professor:export` to Obsidian):
   - When to do this: only needed if the user wants to export to Obsidian
   - Requires the Obsidian Local REST API community plugin to be installed and enabled in Obsidian
   - Provide a complete, copy-pasteable JSON snippet for `.mcp.json`:
     ```json
     {
       "mcpServers": {
         "obsidian": {
           "command": "npx",
           "args": ["-y", "mcp-obsidian"],
           "env": {
             "OBSIDIAN_API_KEY": "your-obsidian-rest-api-key-here",
             "OBSIDIAN_HOST": "127.0.0.1",
             "OBSIDIAN_PORT": "27123"
           }
         }
       }
     }
     ```
   - Note: Get the API key from Obsidian → Settings → Local REST API plugin
   - Note: Default port is 27123 unless changed in the plugin settings

7. **Commands** — A Markdown table listing all 14 commands and one-line descriptions. Categories:
   - Course Navigation: new-topic, next, done, review, syllabus, progress
   - Getting Help: hint, stuck, discuss, quiz
   - Capstone: capstone, capstone-review
   - Notes & Export: note, export

8. **Scope / Limitations** (short section):
   - Claude Code only (v1.0)
   - Multi-agent / multi-platform support is a future consideration
   - The professor will never complete your exercises for you — that is the whole point

**Formatting guidance (Claude's discretion):**

- Code blocks with language hints (`bash`, `json`)
- Keep total length reasonable — comprehensive but not padded
- Tone: friendly, practical, direct
