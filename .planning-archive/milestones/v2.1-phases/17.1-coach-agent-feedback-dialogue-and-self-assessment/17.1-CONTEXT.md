# Phase 17.1: Coach Agent - Context

**Gathered:** 2026-03-15
**Status:** Ready for planning

<domain>
## Phase Boundary

Create Coach agent that owns `professor:review`, `professor:done`, `professor:stuck`. Professor routes to Coach for these commands. Coach introduces self-assessment dialogue before any feedback.

**Phase 17 context:** Exercise generation already exists (Phase 17). Coach adds the feedback dialogue layer.

</domain>

<decisions>
## Implementation Decisions

### Core Principle
- Every Coach interaction opens with self-assessment question before Coach says anything
- "Before I look at your work — what do you think about it? What's working, and what are you unsure about?"
- Learner's self-assessment shapes everything Coach says next

### Review Flow
- Coach reads: COURSE.md + active exercise file + reasoning trail + attempt log
- Coach asks self-assessment question
- Coach asks ONE probing question based on their response
- Coach gives structured feedback (what's working, gap as question, one concept, one next action)
- Coach appends round to reasoning trail (max 5 rounds per section)

### Done Gate
- Coach reads reasoning trail
- Coach asks: "Looking back on this section — what was the hardest concept?"
- Coach asks follow-up targeting weakest point
- If solid → routes to Professor to mark done
- If shaky → one more round, then Coach decides (mark done with ⚠️ watch-this flag OR ask learner to try again)

### LEARNING-LOG.md
- New file per course directory
- Stores Reasoning Trail (Coach owned) and Attempt Log (Spotter writes, Coach reads)
- Separate from COURSE.md to keep COURSE.md lean

### Claude's Discretion
- Exact wording of self-assessment prompts
- How many rounds before escalating
- When to use watch-this flag vs ask to retry

</decisions>

## Specific Ideas

### Reasoning Trail Format
```markdown
## 🗣️ Reasoning Trail

### Section 2.1 — Closures

⚠️ watch-this: boundary conditions

Round 1 — 2026-03-14
  Learner: "I think the loop is right but edge cases worry me"
  Coach asked: "What happens when the input is empty?"
  Concept: boundary conditions
```

### Attempt Log Format
```markdown
## 📋 Attempt Log

### Section 2.1 — Closures

- 14:22 — "hmm this isn't working" → sticking point: loop skips last element
- 14:35 — check-in: "started but hit a wall" → edge case handling
- 14:58 — check-in: "ready for review" → routed to Coach
```
