**Researched:** 2026-03-15
**Domain:** Claude Code plugin agent development (Markdown-based)
**Confidence:** HIGH

## Summary

Phase 17.1.1.1 creates the Navigator agent that bridges sections by showing learners how concepts connect. It follows the established Claude Code plugin pattern (Markdown agents with frontmatter, commands registered in plugin.json) used by Coach and Spotter. The Navigator is triggered automatically between sections rather than invoked manually, offering three bridge formats (text summary, concept map, Socratic prompts) and maintaining a "Concept Thread" in LEARNING-LOG.md.

**Primary recommendation:** Implement Navigator as a Markdown agent with frontmatter, create a command file for optional manual invocation, and extend LEARNING-LOG.md with a "Concept Thread" section following the existing Reasoning Trail and Attempt Log patterns.

### Pattern 2: Hybrid Trigger Flow
**What:** Navigator appears at two points with different depth
**When to use:** After `professor:done` (brief) and `professor:next` (fuller)
**Flow:**
1. After `professor:done` completes section N:
   - Read LEARNING-LOG.md for current section's key concepts
   - Generate brief bridge (2-3 sentences)
   - Ask learner to choose format preference (text/concept-map/Socratic)
   - Show bridge, append to Concept Thread
   
2. After `professor:next` shows section N+1:
   - Read LEARNING-LOG.md for section N concepts
   - Read LECTURE.md for section N+1 topics
   - Generate fuller bridge with explicit connections
   - Present three format options, show chosen format
   - Append comprehensive bridge to Concept Thread

### Pattern 3: LEARNING-LOG.md Extension
**What:** Add "Concept Thread" section alongside existing sections
**When to use:** Navigator needs to read/write concept connections
**Format:**
```markdown
## 🧭 Concept Thread

### Section 2 → Section 3
**Format used:** text-summary
**Previous:** Closures — functions that "remember" their scope
**Next:** Higher-order functions — functions that take/return functions
**Connection:** "Closures enable higher-order functions because you can 
return a function that still has access to its original scope."

### Section 3 → Section 4
**Format used:** concept-map
**Thread:** Higher-order → enables → callbacks → enables → event handlers

⚠️ Forward reference from Section 1:
  Previously: "You identified that edge cases matter" → Now: "This connects 
  to defensive programming in error handling"
```

## Common Pitfalls

### Pitfall 1: Automatic Invocation Without User Consent
**What goes wrong:** Navigator interrupts flow between sections without learner control
**Why it happens:** Treating Navigator as mandatory instead of optional enhancement
**How to avoid:** 
- Make Navigator additive, not blocking
- After `professor:done`, show brief bridge then ask "Continue to next section?"
- After `professor:next`, show bridge then let learner start reading lecture
- Provide `professor:navigator` for manual invocation anytime
**Warning signs:** Learner expresses frustration at interrupted flow

### Pitfall 2: Over-Complicating Concept Extraction
**What goes wrong:** Trying to auto-detect "key concepts" using NLP or AI analysis
**Why it happens:** Attempting to infer concepts from lecture content programmatically
**How to avoid:**
- Read LECTURE.md for explicit "concept" mentions in headers/content
- Trust the section title as a key concept
- For Coach's "watch-this" flags, thread those forward explicitly
- Keep it simple: extract what humans already wrote, don't generate new analysis
**Warning signs:** Research into NLP libraries, complex parsing logic

### Pitfall 3: Concept Map Without Visual Design
**What goes wrong:** ASCII art concept maps that are hard to read
**Why it happens:** Attempting elaborate box-drawing when simple arrows work better
**How to avoid:**
- Use simple arrows: `X → Y → Z`
- For "enables" relationships: `X ─ enables ─→ Y`
- Keep to 3-4 items max per line
- Example:
  ```
  closures ─ enables ─→ higher-order functions ─ enables ─→ callbacks
  ```

# Navigator Agent — Section Bridges and Concept Threading

You are **Navigator** — a learning bridge agent that helps learners see how concepts connect 
across sections. You specialize in showing "what you just learned → what comes next" bridges.

---

## Core Principle

Navigator is additive, never blocking. Present the bridge, then let the learner continue. 
Never force a bridge interaction — offer it as a helpful pause between sections.

---

## Activation Triggers

### After professor:done (Brief Bridge)
1. Read LEARNING-LOG.md for current section concepts
2. Read LECTURE.md for section title and key topics
3. Ask learner format preference (text/concept-map/Socratic)
4. Generate 2-3 sentence bridge
5. Append to Concept Thread in LEARNING-LOG.md

### After professor:next (Fuller Bridge)
1. Read LEARNING-LOG.md for previous section concepts
2. Read LECTURE.md for both previous and next section topics
3. Ask learner format preference (or use stored preference)
4. Generate comprehensive bridge with explicit connections
5. Check for Coach's "watch-this" flags to thread forward
6. Append to Concept Thread in LEARNING-LOG.md

---

## Bridge Formats

### Text Summary
"In Section {N} you learned {concept}. In Section {N+1} you'll build on this by learning 
{next-concept}. The connection is {how they relate}."

### Concept Map
"Section {N} concepts:
  {concept1} ─ connects to ─→ {concept2}
  {concept2} ─ enables ─→ {concept3}

Section {N+1} builds on: {concept1}, {concept3}"

### Socratic Prompts
"Before you dive into {next-section}, consider:
- What would happen if you tried to use {previous-concept} without {prerequisite}?
- How might {new-concept} change the way you think about {previous-concept}?
- What question from Section {N} is now answered in Section {N+1}?"

## Open Questions

1. **Format preference persistence**
   - What we know: Learner chooses format per-bridge
   - What's unclear: Should format preference be stored and auto-used?
   - Recommendation: Store in LEARNING-LOG.md as "preferred_format: text|concept-map|socratic" and use as default

2. **Concept extraction depth**
   - What we know: Section titles are explicit, LECTURE.md has concept mentions
   - What's unclear: How much inference should Navigator do vs. trusting humans?
   - Recommendation: Keep simple — extract from explicit mentions only, no inference

3. **Cross-course threading**
   - What we know: Navigator threads within a single course
   - What's unclear: Should insights thread across multiple courses?
   - Recommendation: Out of scope for v2.0 — focus on single-course threading first
